Живые префабы и синхронизация

Когда вы создаёте префаб из сущности (ПКМ в Hierarchy → Save as prefab) или с нуля (File → New prefab), каждый экземпляр на сцене получает ссылку properties.prefabId. После правок в Prefab Editor кнопка Sync instances обновляет геометрию, компоненты и дочерние объекты всех копий во всех сценах проекта, сохраняя их мировые позиции.

Террейн: слои, размеры и кисть Scatter

  • Неограниченные слои материалов: добавляйте любое число слоёв поверх базового (трава, асфальт, грязь, бетон). Ползунок Hard ↔ Soft для каждого слоя задаёт резкость границ смешивания.
  • Изменение размеров (Resize Terrain): быстрые пресеты 16м / 32м / 64м / 128м и ручной ввод ширины/глубины/сегментов с билинейной передискретизацией карты высот и весов всех слоёв.
  • Кисть Multi-Model Scatter / Erase scatter: выберите несколько моделей или префабов (деревья, кусты, трава, камни), задайте плотность, разброс масштаба, случайный поворот по Y и привязку к нормали — кисть автоматически расставляет объекты по рельефу террейна.
Глава 3Ассеты

Импорт 3D-моделей и Model Editor (v1.2–v2.1)

Встроенная конвертация через assimpjs WASM, настройка слотов материалов и нарезка одной дорожки анимации на отдельные клипы.

Miniforge хранит 3D-модели в бинарном формате glTF 2.0 (.glb) — самом быстром и компактном формате для WebGL2. При импорте других форматов редактор автоматически конвертирует их в .glb прямо на лету.

Трёхуровневый конвейер импорта

  1. Встроенный Assimp WASM (assimpjs): работает «из коробки» во всех сборках — в браузере, Windows, macOS и Linux без установки сторонних программ. Поддерживает .x, .fbx, .smd, .obj, .dae, .3ds, .ms3d, .b3d, .ply, .stl, .md2, .md3, .md5mesh. Вместе с моделью можно перетащить сопутствующие текстуры и .mtl-файлы.
  2. Чистый TypeScript-парсер .x → .glb (xToGlb.ts): мгновенный резервный конвертер для текстовых DirectX .x файлов со скелетом и анимациями.
  3. Нативный Assimp CLI (Desktop Tauri): дополнительный fallback в десктопной версии, если системный бинарник assimp доступен в PATH.
Экспорт обратно в .glb для правок в Blender

В заголовке Model Editor есть кнопка .glb — она сохраняет сконвертированную модель на диск. Удобно, если нужно поправить ориентацию осей или скиннинг в Blender и загрузить обратно.

Настройка материалов в Model Editor

На вкладке Materials отображаются все меш-слоты (Part #0, #1, ...) с числом треугольников, цветом и флагом наличия встроенной текстуры. Для каждого слота доступны два режима:

  • Назначение Material Asset проекта: выберите любой существующий материал из выпадающего списка или нажмите + New material, чтобы создать новый ассет на базе цвета слота и сразу привязать его.
  • Быстрые оверрайды встроенного GLB-материала: оставив Embedded GLB default, можно менять Tint color, Opacity, Roughness, Metalness, Emissive, Unlit, Pixelated и Double-sided, сохраняя оригинальную диффузную текстуру из файла.

Нарезка анимаций из одной дорожки (Timeline Slicer)

Многие модели (особенно из паков .x, .fbx, Mixamo или Source) приходят с одной длинной дорожкой, где подряд записаны все движения. Вкладка Animations решает эту задачу неразрушающе — сам файл .glb не перезаписывается, а описания клипов хранятся в asset.properties.clips и нарезаются рендерером при загрузке с точной интерполяцией границ (включая SLERP кватернионов вращения костей).

  1. Выберите исходную дорожку в Source track и удобную частоту кадров (24 / 30 / 60 fps) для отображения кадров.
  2. Прокрутите ползунок таймлайна до начала движения и нажмите [ Set Start, затем до конца — и нажмите ] Set End (либо введите точные секунды вручную).
  3. Включите галочку Loop range, чтобы зациклить воспроизведение строго внутри выделенного зелёного отрезка и точно подогнать стык анимации.
  4. Введите имя нового клипа (например, Idle, Walk, Run, Attack) и нажмите Add clip, затем Save changes.

Сразу после сохранения новые клипы появляются в выпадающем списке компонента Animation в инспекторе, в полях walkClip / idleClip у NavAgent и доступны из кода через api.animation.play(id, 'Walk') и api.animation.crossfade(id, 'Run', 0.2).

Глава 4Blueprints

Визуальное программирование: Event Graph (Blueprints)

Аналог Unreal Engine Blueprints: 65+ нод под всё API движка, переменные (Local / HUD / WorldState), Exposed Variables и кастомные функции.

Компонент Event Graph (type: "eventGraph") заменяет устаревшие линейные правила на полноценный нодовый граф, который хранится как переиспользуемый ассет type: "graph" (меню Assets → New Event Graph). Старые Event Rule сохраняют полную обратную совместимость.

  • Типизированные пины и провода Безье: белый exec (поток выполнения), красный boolean, зелёный number, фиолетовый string, золотой vec3, голубой entity (со встроенной 3D-пипеткой выбора объекта со сцены) и серый any.
  • Переменные (My Blueprint → Variables): три области видимости — Local (локально в экземпляре), HUD (vars) (автосинхронизация с интерфейсом) и WorldState (переживает смену сцен). Флаг Editable in Inspector выводит переменную прямо на сущность для переопределения.
  • Кастомные функции (Functions): создавайте собственные функции с произвольными входными и выходными параметрами (Function Entry → логика → Return) и вызывайте их из основного EventGraph или других функций через ноду Call Function().
  • Покрытие всего GameAPI: события жизненного цикла, Branch / Sequence / ForLoop / Delay / DoOnce / FlipFlop / Gate, математика/векторы, Player / Camera / Physics Raycast, Play / Crossfade Animation, NavAgent, Get Surface Material At, свет, частицы, декали, Tween Move To, звук, UI, сохранения и реклама платформ.

Как устроен Event Graph внутри (интерпретатор, не компиляция в JS)

Event Graph не компилируется в JavaScript — в рантайме работает интерпретатор графа (packages/runtime/src/eventGraph.ts → createEventGraphLifecycle). Граф хранится в проекте как чистый JSON-ассет типа graph и не использует eval/new Function, поэтому без проблем проходит строгий CSP на веб-порталах (Яндекс Игры, Poki).

  • Поток выполнения (белые Exec-пины): распространяется вперёд от красного Event-узла через runFromPin() с защитой от бесконечных циклов (MAX_STEPS = 2000, MAX_CALL_DEPTH = 48).
  • Поток данных (цветные Data-пины): вычисляется лениво назад (evalInput → evalOutput) по запросу узла и кэшируется внутри одного прохода ExecScope.

Рецепт 1. Звук шагов по материалу под ногами (террейн + любые 3D-модели)

ts
export default function (api: GameAPI) {
  let stepTimer = 0
  const footstepMap: Record<string, string> = {
    Asphalt: 'sfx-step-asphalt',
    Grass: 'sfx-step-grass',
    Mud: 'sfx-step-mud',
    Wood: 'sfx-step-wood',
  }
  return {
    onUpdate(dt: number) {
      const [mx, mz] = api.input.move
      if (!api.player.isGrounded || Math.hypot(mx, mz) < 0.15) return
      stepTimer -= dt * (api.player.isSprinting ? 1.55 : 1)
      if (stepTimer > 0) return
      stepTimer = 0.42

      // Работает и на террейне (учитывает слой кисти), и на любом 3D-меше
      const hit = api.materials.getSurfaceAt(api.player.position, [0, -1, 0], 2.0)
      const sfx = (hit && footstepMap[hit.materialName]) || 'sfx-step-default'
      api.audio.play(sfx, { bus: 'sfx', volume: 0.7, pitch: 0.92 + Math.random() * 0.16 })
    },
  }
}

Рецепт 2. ИИ-патруль NPC на NavAgent с нарезанными анимациями

ts
export default function (api: GameAPI) {
  const waypoints: [number, number, number][] = [
    [0, 0, 0], [12, 0, 4], [10, 0, -10], [-4, 0, -6],
  ]
  let idx = 0
  let wait = 0

  const goNext = () => {
    api.nav.moveAgent(api.entity.id, waypoints[idx], {
      speed: 2.4,
      stopDistance: 0.45,
      walkClip: 'Walk',   // клип, нарезанный в Model Editor
      idleClip: 'Idle',
      crossfade: 0.25,
    })
  }
  return {
    onStart() { goNext() },
    onUpdate(dt: number) {
      if (api.nav.isAgentMoving(api.entity.id)) return
      wait += dt
      if (wait >= 2.0) {
        wait = 0
        idx = (idx + 1) % waypoints.length
        goNext()
      }
    },
  }
}

Рецепт 3. Динамический цикл дня и ночи + фонарик + Sun Rays

ts
export default function (api: GameAPI) {
  let hour = 10 // 0..24
  let torchOn = false
  return {
    onUpdate(dt: number) {
      hour = (hour + dt * 0.15) % 24
      const angle = ((hour - 6) / 24) * Math.PI * 2
      const sunY = Math.sin(angle)
      const dayFactor = Math.max(0, sunY)

      api.environment.setSun([Math.cos(angle), Math.max(0.08, sunY), 0.35],
        dayFactor > 0.2 ? '#fff4de' : '#ff9f68', 0.25 + dayFactor * 1.45)
      api.environment.setAmbient(0.22 + dayFactor * 0.65)
      api.environment.setFog(dayFactor > 0.1 ? 0.012 : 0.028, dayFactor > 0.1 ? '#b7c7d6' : '#141c28')

      if (api.input.pressed('Flashlight')) {
        torchOn = !torchOn
        api.lights.setFlashlight({ enabled: torchOn, color: '#fff3d6', intensity: 3.2, range: 22, angle: 0.55 })
      }
    },
  }
}

Система плагинов (Plugin API v2.2): создание, импорт и разработка

Архитектура плагинов Miniforge Engine v2.6, формат .mfplugin.json, полный справочник EditorPluginContext и RuntimePluginContext, разбор 4 встроенных примеров от простого HUD до RPG-инвентаря.

Начиная с версии v2.2, в Miniforge Engine встроена полноценная модульная система плагинов. Плагины хранятся прямо в проекте как ассеты типа plugin, поддерживают экспорт/импорт в одном файле (.mfplugin.json или .js), умеют расширять как Редактор (добавлять команды в верхнее меню Plugins, модифицировать сцену и ассеты), так и Рантайм (регистрировать собственные Behavior-компоненты, глобальные сервисы, HUD-интерфейсы и хуки игрового цикла).

1. Где управлять плагинами и как их импортировать

  • Создание нового плагина: в верхнем меню нажмите Plugins → + New Plugin или в панели Assets → + New → Plugin. Откроется встроенный Plugin Manager с редактором метаданных, редактором кода, валидатором синтаксиса и кнопкой Save changes.
  • Импорт готовых плагинов: перетащите файл .mfplugin.json прямо на панель Assets (Drag & Drop) или нажмите Import .mfplugin.json / .js внутри Plugin Manager. Импортированный плагин автоматически включается и активирует свои пункты в меню Plugins.
  • Экспорт и распространение: кнопка Export .mfplugin.json выгружает самодостаточный JSON-манифест со всем кодом и метаданными — его можно передать другому разработчику или перенести в другой проект Miniforge.
  • Встроенная галерея примеров: во вкладке Example Plugins внутри Plugin Manager доступны 4 готовых плагина возрастающей сложности с установкой в один клик (Install).

2. Формат манифеста .mfplugin.json

Каждый плагин описывается структурой PluginManifest (определена в packages/project-schema/src/plugins.ts). Поле code содержит обычный JavaScript-модуль (CommonJS-стиль с объектом exports):

json
{
  "id": "my-custom-plugin",
  "name": "My Custom Plugin",
  "version": "1.0.0",
  "author": "Indie Dev",
  "description": "Краткое описание возможностей плагина",
  "category": "runtime",
  "enabled": true,
  "code": "exports.registerRuntime = function(ctx) { ... };"
}
ПолеТипОписание
idstringУникальный идентификатор плагина (slug), например fps-counter-hud.
namestringОтображаемое название плагина в списке ассетов и Plugin Manager.
versionstringВерсия плагина в формате SemVer (например, 1.0.0).
authorstringИмя автора или студии.
category"gameplay" | "editor" | "ui" | "world" | "utility" | "runtime"Категория для визуальной группировки в менеджере плагинов.
enabledbooleanФлаг активности. Отключённый плагин остаётся в проекте, но его хуки не запускаются ни в редакторе, ни в рантайме.
codestringИсходный JavaScript-код плагина с точками входа exports.registerEditor и/или exports.registerRuntime.

3. Точки входа и жизненный цикл плагина

Код плагина компилируется изолированно через new Function('exports', code) и может экспортировать одну или обе функции регистрации:

  • exports.registerEditor(ctx) — вызывается в редакторе при загрузке проекта, переключении флага enabled или сохранении кода плагина. Используется для регистрации пунктов меню Plugins и инструментов генерации контента на сцене.
  • exports.registerRuntime(ctx) — вызывается при старте игровой сессии (Play в редакторе или экспортированный билд) до инициализации сущностей сцены. Регистрирует кастомные Behavior-компоненты, сервисы и хуки игрового цикла.

Ниже показан минимальный гибридный плагин, который одновременно добавляет инструмент в редактор и регистрирует кастомный Behavior в рантайме:

exports.registerEditor = function(ctx) {
  ctx.registerMenuAction({
    id: 'spawn-beacon', label: 'Spawn Rotating Beacon',
    run: function() {
      ctx.patchScene(function(scene) {
        var entity = {
          id: ctx.uid('beacon'), name: 'Signal Beacon',
          transform: { position: [0, 1.5, 0], rotation: [0, 0, 0], scale: [0.6, 1.8, 0.6] },
          components: [
            { type: 'mesh', primitive: 'cylinder', color: '#f59e0b' },
            { type: 'behavior', kind: 'beaconSpinner', params: { speed: 2.2 } }
          ]
        };
        return Object.assign({}, scene, { entities: scene.entities.concat([entity]) });
      });
      ctx.notify('Signal Beacon добавлен на сцену');
    }
  });
};

8. Рекомендации по разработке и отладке плагинов

  • Проверяйте синтаксис до запуска: кнопка Validate в Plugin Manager прогоняет компиляцию кода и сразу показывает строку ошибки без перезапуска сцены.
  • Всегда очищайте ресурсы в onDestroy: если плагин монтирует DOM-элементы через api.ui.mount() или вешает слушатели window.addEventListener, удаляйте их в ctx.onDestroy, чтобы не оставлять «призраков» после выхода из режима Play.

  • Сохраняйте прогресс через api.worldState: данные, записанные в worldState (как в примере rpg-inventory-loot), автоматически переживают смену сцен и участвуют в системе сохранений движка.
