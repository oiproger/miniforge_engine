# Переход Miniforge на LittleJS

LittleJS можно рассматривать как основной движок для 2D и 3D. У него есть собственный Render3D, объекты сцены, камеры, освещение, инстансинг, карты высот и коллизии по сетке. Загрузчик glTF/GLB поддерживает анимацию узлов и скелетов. Для прототипа выбираем собственный Render3D. Плагин интеграции с Three.js тоже существует, но при его использовании Three.js продолжит входить в проект. Возможности проверены по исходникам ревизии `42619bd`. [Render3D](https://github.com/KilledByAPixel/LittleJS/tree/42619bd28010fb50e400686dcd475eccbd053256/plugins) · [Загрузчик glTF](https://github.com/KilledByAPixel/LittleJS/blob/42619bd28010fb50e400686dcd475eccbd053256/plugins/gltf.js)

## Что предстоит перенести

| Область | Решение |
| --- | --- |
| Сцена и данные | Сохранить формат сцен, ID, иерархию, трансформации и префабы. Адаптер Render3D создаёт объекты по этим данным и переводит мировые и локальные координаты. Проверить вложенные повороты, масштаб, видимость и уничтожение поддерева. |
| Модели и материалы | Сопоставить клипы и событие завершения анимации с текущим API. Проверить текстуры, прозрачность и пользовательские шейдеры. Загрузчик LittleJS пропускает morph targets и карты roughness, metalness и occlusion. Для используемых проектом возможностей добавить адаптер или диагностику до экспорта. |
| Террейн | Сохранить сетку высот, раскраску ячеек, UV и два материала. Из одного массива высот собирать геометрию Render3D и поверхность Rapier. Проверить совпадение диагоналей треугольников, нормалей и высоты под ногами после редактирования. |
| Физика | Сначала оставить Rapier и фиксированный шаг симуляции. Передавать позы тел и треугольники через числа и массивы. Отдельно сравнить MeshCollider LittleJS на ступенях, крутом склоне, сенсорах и динамических телах, прежде чем менять физику. |
| Редактор и игровой API | Изолировать выбор лучом, камеры и манипуляторы viewport. Для новых скриптов определить операции с трансформациями по ID. Проинвентаризировать старые скрипты, получающие Three.js Object3D через GameAPI, и сохранить совместимый профиль до их переноса. Подсказки Monaco должны соответствовать выбранному профилю. |
| Runtime и экспорт | Оставить общими HUD, инвентарь, локализацию, события, правила, сохранения и SDK площадок. Выбирать один графический бэкенд при подготовке Preview и экспорта. Сохранить одного владельца игрового цикла и проверять освобождение ресурсов при Stop. |

## Как принять решение

1. Зафиксировать версию LittleJS и собрать Key Vault на Render3D. Игрок должен собрать три ключа, открыть магазин, увидеть анимацию ворот и перейти в следующую сцену. Добавить окрашенный террейн и пройти тот же маршрут после сохранения и повторного открытия проекта.
2. С одним файлом проекта сравнить обе сборки на одном телефоне. Записать размер ZIP и JS gzip, время до первого управляемого кадра и 95-й перцентиль времени кадра. Проверить внешний вид материалов, положение коллайдеров и работу сенсорного HUD.
3. После проверки игрового пути перенести viewport редактора, произвольные материалы и поддерживаемые скрипты. Прогнать старые архивы и последовательность Preview → Stop → Preview. Проверить состав экспортированного пакета на присутствие Three.js.
4. Переключить новые проекты на LittleJS после достижения функционального паритета. Удаление старого бэкенда привязать к успешной миграции существующих проектов и скриптов.

Это проект миграции. Действующая реализация Miniforge использует Three.js и Rapier. Сравнительные измерения на LittleJS предстоят.
