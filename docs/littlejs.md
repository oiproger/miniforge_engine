# LittleJS как бэкенд для 2D-проектов

Текущий 3D-бэкенд — Three.js. Пакет graphics создаёт сцену и камеры, загружает glTF и воспроизводит анимации. Runtime использует Object3D, Vector3, камеры и Raycaster непосредственно, viewport редактора использует Three.js для выбора и трансформаций. Публичный GameAPI также отдаёт скриптам Object3D. Физика использует Rapier 3D. Babylon.js среди зависимостей проекта отсутствует.

LittleJS подходит для 2D-игр со спрайтами, тайловыми картами и двумерной физикой. Предлагаемый первый этап — отдельный тип проекта с собственным runtime. Переход существующей 3D-игры в 2D требует авторских решений о проекции, арте и коллизиях. [LittleJS](https://github.com/KilledByAPixel/LittleJS)

## Границы пакетов

| Область | Решение |
| --- | --- |
| Формат проекта | Ввести дискриминатор проекта `backend: 'three-3d' \| 'littlejs-2d'`. При отсутствии значения читать `three-3d`. Сериализовать координаты 2D в XY, глубину сортировки отдельным полем. Версионировать 2D-компоненты независимо от формата 3D-сцен. |
| Сессия | Вынести управление сценами, спавном, временем, событиями, переменными, правилами и жизненным циклом из startGame. Общий код оперирует ID сущностей. Бэкенд создаёт представление, применяет трансформации, исполняет фиксированный шаг, выдаёт события контактов и освобождает ресурсы. У каждой игровой сессии один владелец цикла обновления. |
| Рендер и физика | Оставить Three.js и Rapier в 3D-пакете. 2D-пакет отображает сущности через EngineObject, спрайты и TileLayer. Для него завести отдельные компоненты камеры, тайловых столкновений и движения. Публичный интерфейс сообщает возможности выбранного бэкенда. |
| Скрипты | Сохранить существующие типы GameAPI и доступ к Three.js для старых скриптов. Ввести тип общего API для событий, ввода, HUD и операций с сущностями. Предлагать отдельные типы для 2D-трансформаций и направлений. Генерировать подсказки Monaco по профилю проекта. |
| Редактор | Оставить дерево объектов, ассеты, историю изменений и редактор HUD общими. Выделение, преобразование координат указателя, перемещение камеры и инструменты сцены передать адаптеру viewport. Inspector получает каталог компонентов от бэкенда. |
| Сборка | Выбирать runtime до сборки или загрузки Preview. Для каждой цели собирать отдельный entry point и проверять дерево модулей. Preview и экспорт должны использовать один и тот же entry point. SDK площадок, локализация и DOM HUD остаются общими. |

## Что переносится

Тексты, изображения, аудио, экраны HUD и правила, использующие только переменные и события, можно переиспользовать. На стадии проверки проекта ссылка на неподдерживаемый компонент должна открывать соответствующий объект в Inspector. Для GLB, скелетных клипов, 3D-шейдеров, terrain и 3D-коллайдеров потребуется 2D-представление. Например, высотную карту уровня дизайнер может интерпретировать как тайлы с препятствиями. Преобразование следует сохранять в новый проект с отчётом о пропущенных объектах.

## Порядок внедрения и приёмка

1. Зафиксировать регрессионные сценарии старых проектов и выделить общий жизненный цикл. Проверить загрузку Coin Rush и Key Vault, скрипты с Object3D, сцену с террейном и открытие старых архивов.
2. В отдельном прототипе LittleJS воспроизвести комнату с игроком, стеной, предметом и переходом между HUD и инвентарём. Проверить Preview → Stop → Preview, освобождение обработчиков ввода и ресурсов, запуск двух независимых preview в iframe.
3. Подключить 2D-viewport, каталог компонентов, диагностику и экспорт. Прогнать одинаковую последовательность действий в редакторе и автономном веб-пакете, проверить клавиатуру и сенсорное управление.
4. Сравнить размер JS gzip, время до первого управляемого кадра и память на одном устройстве. Проверить, что 2D-архив запускается без модулей Three.js и Rapier 3D. После этого решать, какие дополнительные жанры и инструменты оправдывают поддержку второго бэкенда.
